feat: 移动端适配 + 微信连接超时护栏

## 移动端适配

侧边栏改双形态：
- 桌面（≥lg）保持固定左侧栏，与 LDC 一致
- 移动（<lg）改成抽屉：顶栏汉堡按钮滑出、半透明遮罩、点遮罩/选中菜单/按 Esc 关闭，
  打开时锁住背景滚动（否则手指滑动会带动背后页面）

顶栏：
- 左侧加汉堡按钮（桌面隐藏）
- 顶部留 env(safe-area-inset-top)，避免 iPhone 刘海压住内容
- 用户信息在窄屏收起，只留头像与退出

全局规则（styles.css）：
- h-svh 用 100dvh 兜底：手机地址栏收起/展开不再截断内容
- 输入控件在窄屏强制 16px：iOS 聚焦时不会自动放大页面
- 触屏上按钮最小 36px（xs/icon-sm 原本 24~28px，手指点不准）
- .row-actions：窄屏让行内按钮组独占一行，不再把行撑宽
- @media (hover:none) 兜底：不依赖 hover 才显示操作

其他：
- 页签条改成整条可横向滚动（后台 6 个页签窄屏放不下；换行易误点）
- 页内容内边距 px-4/px-6 分级、底部留 safe-area
- index.html 加 viewport-fit=cover 与 theme-color（地址栏跟随主题）
- 状态面板资源卡在窄屏压到 min-h 80px，经验构成改单列

## 微信连接超时护栏（修"永远卡在正在连接"）

微信 SDK 内部 HTTP 请求**没有超时**。实测 bot.run() 一直不返回，
通道永远卡在「正在用已保存的登录状态连接…」，重试逻辑根本没机会执行。

改动：
- 把 bot.run() 拆成 bot.login() + bot.start()，分别套超时
  （连接 45s / 启动 15s / 创建客户端 15s）
- 超时即失败 → 走重试；失败时关掉半成品客户端，避免后台轮询残留

（顺带：不用 backdrop-blur，项目视觉规范禁止玻璃拟态）

测试：411 项全绿；typecheck / lint / build 通过
